# Follow-up 1.0.2: valid Windows replacement backup path

The target-host activation of 1.0.1 failed before starting solvers. The user read the retained state.tmp, which contained:

`WINDOWS_GUARD_ERROR: Exception calling "Replace" with "3" argument(s): "The path is not of a legal form."`

The initial File.Move had published state.json successfully. The first File.Replace failed. This establishes the failing operation in 1.0.1; it does not prove the cause of the earlier 1.0.0 nighttime abort.

Version 1.0.2 supplies a concrete same-directory backup path `state.previous.json` instead of `$null`. This avoids dependence on PowerShell's null-to-String binding, the likely source of the invalid backup path. The backup is a single small file reused on replacement, not a growing history. Microsoft documents replacement of an existing backup file: https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace . No blanket atomicity guarantee across WSL is asserted.

Guard.read now rejects an exited Windows observer immediately and includes its directory and the draft error document. This prevents a failed writer's first still-fresh publication from masking its exit during activation.

All reserve thresholds, bounded read retries, 15-second real Windows activation test, solver settings, input identities and mathematical coverage remain unchanged. No new production run was started locally. The actual Windows replacement call must still pass the required target-host test; Linux regression controls cannot certify that API path.
