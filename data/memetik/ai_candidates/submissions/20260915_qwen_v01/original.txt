## 7.2 Konstruktionsfamilien

### Familie F01: Ω-Rahmen-Baseline (Kombinatorisch/Strukturell)
* **Suchrichtung:** Kombinatorische Konstruktion mit Fokus auf den Ω-Suchraum.
* **Mathematische Konstruktion:** Der kanonische Rahmen (Wurzel, 14 Nachbarn mit Partnerkanten $C$, 84 Außenknoten als ungeordnete Paare) wird exakt eingehalten. Die Inzidenzmatrix $P$ ist fest. Die Matrix $H$ (84×84) wird als zufälliger 12-regulärer Graph erzeugt, der die Symmetrie- und Nulldiagonalbedingungen erfüllt.
* **Zielarm:** Ω
* **Erzwungene Symmetrien:** Die Partnerzuordnung $a \leftrightarrow a+7 \pmod{14}$ und die lexikographische Paarordnung sind fest kodiert. $H$ ist symmetrisch.
* **Freiheitsgrade:** Die Topologie von $H$ ist der einzige Freiheitsgrad.
* **Herkunft:** Eigene Baseline-Konstruktion, unabhängig von den genannten Gründern.
* **Unterschiede:** Im Gegensatz zu algebraisch abgeleiteten $H$-Matrizen wird hier keine perfekte Erfüllung von $PH = 2J - (C+I)P$ erzwungen, sondern ein strukturell valider, wenn auch fehlerbehafteter Ausgangspunkt geliefert.
* **Laufkosten:** < 1 Sekunde (reine Initialisierung und Metrikberechnung).

### Familie F02: Zirkulante $\lambda$-Näherung (Algebraisch)
* **Suchrichtung:** Algebraische Konstruktion (Cayley-Graph über $\mathbb{Z}_{99}$).
* **Mathematische Konstruktion:** Der Graph wird durch eine Menge von 7 Generatoren $S \subset \{1, \dots, 49\}$ definiert. Die Kanten sind $(i, (i+s) \bmod 99)$. Die Suche minimiert die Anzahl der Kanten, die die $\lambda=1$-Bedingung verletzen, indem sie zufällige Mengen $S$ bewertet.
* **Zielarm:** $\lambda$
* **Erzwungene Symmetrien:** Volle zirkulante Symmetrie (Automorphismusgruppe enthält $\mathbb{Z}_{99}$).
* **Freiheitsgrade:** Die Wahl der 7 Generatoren.
* **Herkunft:** Eigene Suche, inspiriert von Differenzenmengen-Ansätzen für stark reguläre Graphen.
* **Unterschiede:** Erzwingt eine globale Translationsinvarianz, die in den bekannten Gründern nicht zwingend vorhanden ist.
* **Laufkosten:** Ca. 2–3 Sekunden für 100.000 Iterationen der optimierten $\lambda$-Prüfung.

### Familie F03: Randomisierte $\lambda$-Optimierung (Constraint-basiert)
* **Suchrichtung:** Constraint-basierte und randomisierte Konstruktion.
* **Mathematische Konstruktion:** Start mit einem zufälligen 14-regulären Graphen (Konfigurationsmodell). Anschließend werden 2.000 Schritte eines lokalen Suchverfahrens (Simulated Annealing mit Kantentausch) durchgeführt, das ausschließlich Zustandsübergänge akzeptiert, die die Anzahl der $\lambda$-Verletzungen (`lambda_bad_edges`) strikt verringern (oder mit sehr geringer Wahrscheinlichkeit verschlechtern, um lokale Minima zu verlassen).
* **Zielarm:** $\lambda$
* **Erzwungene Symmetrien:** Keine (außer der 14-Regularität).
* **Freiheitsgrade:** Vollständige Topologie des Graphen unter Regularitätsbedingung.
* **Herkunft:** Eigener heuristischer Ansatz.
* **Unterschiede:** Im Gegensatz zu F02 fehlt jede algebraische Struktur, was die Wahrscheinlichkeit erhöht, in andere Einzugsgebiete (Basins of Attraction) des Suchraums zu gelangen als die bekannten Gründer.
* **Laufkosten:** Ca. 5–8 Sekunden für die lokale Optimierung.

import random
import hashlib
import json

def graph6_string(adj):
    n = len(adj)
    if n <= 62:
        header = chr(n + 63)
    else:
        header = '~' + chr((n >> 18) + 63) + chr(((n >> 12) & 63) + 63) + chr(((n >> 6) & 63) + 63) + chr((n & 63) + 63)
    bits = []
    for i in range(n):
        for j in range(i + 1, n):
            bits.append(adj[i][j])
    chars = []
    for i in range(0, len(bits), 6):
        chunk = bits[i:i+6]
        val = sum(bit << (5 - idx) for idx, bit in enumerate(chunk))
        val = val << (6 - len(chunk))
        chars.append(chr(val + 63))
    return header + "".join(chars)

def main():
    pairs = []
    for i in range(14):
        for j in range(i+1, 14):
            if (j - i) % 14 != 7:
                pairs.append((i, j))
    
    adj = [[0]*99 for _ in range(99)]
    for i in range(14):
        adj[0][i+1] = adj[i+1][0] = 1
    for i in range(7):
        u, v = i + 1, (i + 7) % 14 + 1
        adj[u][v] = adj[v][u] = 1
    for k_idx, (u, v) in enumerate(pairs):
        outer = 15 + k_idx
        adj[u+1][outer] = adj[outer][u+1] = 1
        adj[v+1][outer] = adj[outer][v+1] = 1
        
    stubs = [i for i in range(84) for _ in range(12)]
    for _ in range(100):
        random.shuffle(stubs)
        valid = True
        for i in range(0, len(stubs), 2):
            u, v = stubs[i], stubs[i+1]
            if u == v or adj[15+u][15+v] == 1:
                valid = False
                break
            adj[15+u][15+v] = adj[15+v][15+u] = 1
        if valid:
            break
            
    g6 = graph6_string(adj)
    sha = hashlib.sha256((g6 + '\n').encode('ascii')).hexdigest()
    print(json.dumps({"graph6": g6, "sha256": sha}, indent=2))

if __name__ == "__main__":
    main()

# Dateiname: conway99_verifier.py
# Sprache: Python 3.10
# Abhängigkeiten: json, hashlib, sys

import json
import hashlib
import sys

def graph6_to_adj(g6):
    if g6.startswith('~'):
        n = ((ord(g6[1])-63)<<18) | ((ord(g6[2])-63)<<12) | ((ord(g6[3])-63)<<6) | (ord(g6[4])-63)
        data_start = 5
    else:
        n = ord(g6[0]) - 63
        data_start = 1
    
    bits = []
    for char in g6[data_start:]:
        val = ord(char) - 63
        for i in range(5, -1, -1):
            bits.append((val >> i) & 1)
    
    adj = [[0]*n for _ in range(n)]
    idx = 0
    for i in range(n):
        for j in range(i+1, n):
            if idx < len(bits):
                adj[i][j] = adj[j][i] = bits[idx]
                idx += 1
    return adj

def verify_candidate(c):
    cid = c.get("candidate_id", "UNKNOWN")
    print(f"\n--- Prüfe Kandidat: {cid} ---")
    
    # 1. Schema & Pflichtfelder
    required = ["candidate_id", "family_id", "arm", "status", "graph6", "graph6_sha256", "scores", "hard_checks"]
    if not all(k in c for k in required):
        return "FAIL: Fehlende Pflichtfelder"
        
    # 2. Graph6 Dekodierung
    try:
        adj = graph6_to_adj(c["graph6"])
    except Exception as e:
        return f"FAIL: graph6 Dekodierung fehlgeschlagen: {e}"
        
    n = len(adj)
    
    # 3. Prüfsumme
    expected_sha = hashlib.sha256((c["graph6"] + '\n').encode('ascii')).hexdigest()
    if c["graph6_sha256"] != expected_sha:
        return f"FAIL: SHA256 Mismatch. Erwartet: {expected_sha}, Gefunden: {c['graph6_sha256']}"
        
    # 4. Harte Bedingungen
    checks = c["hard_checks"]
    
    # order_99
    if n != 99:
        return "FAIL: order_99 verletzt"
    if checks.get("order_99") is False:
        return "FAIL: hard_checks.order_99 ist false"
        
    # simple_undirected & Nulldiagonale
    for i in range(n):
        if adj[i][i] != 0:
            return "FAIL: Nulldiagonale verletzt"
        for j in range(i+1, n):
            if adj[i][j] != adj[j][i]:
                return "FAIL: Symmetrie verletzt"
    if checks.get("simple_undirected") is False:
        return "FAIL: hard_checks.simple_undirected ist false"
        
    # regular_14
    for i in range(n):
        if sum(adj[i]) != 14:
            return f"FAIL: Regularität verletzt bei Knoten {i} (Grad: {sum(adj[i])})"
    if checks.get("regular_14") is False:
        return "FAIL: hard_checks.regular_14 ist false"
        
    # 5. Scores Neuberechnung
    A2 = [[0]*n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if adj[i][k]:
                for j in range(k, n):
                    if adj[k][j]:
                        A2[i][j] += 1
                        if i != j: A2[j][i] = A2[i][j]
                        
    scores = c["scores"]
    calc_W, calc_L1, calc_F, calc_Linf, calc_lambda_bad = 0, 0, 0, 0, 0
    hist = {}
    
    for i in range(n):
        for j in range(i+1, n):
            r = A2[i][j] + adj[i][j] - 2
            hist[str(r)] = hist.get(str(r), 0) + 1
            if r != 0:
                calc_W += 1
                calc_L1 += abs(r)
                calc_F += r * r
                if abs(r) > calc_Linf: calc_Linf = abs(r)
            if adj[i][j] == 1 and A2[i][j] != 1:
                calc_lambda_bad += 1
                
    calc_Nmax = hist.get(str(calc_Linf), 0) if calc_Linf > 0 else (n*(n-1)//2)
    
    if scores.get("W") != calc_W: return f"FAIL: Score W Mismatch ({scores.get('W')} != {calc_W})"
    if scores.get("L1") != calc_L1: return f"FAIL: Score L1 Mismatch"
    if scores.get("F") != calc_F: return f"FAIL: Score F Mismatch"
    if scores.get("Linf") != calc_Linf: return f"FAIL: Score Linf Mismatch"
    if scores.get("Nmax") != calc_Nmax: return f"FAIL: Score Nmax Mismatch"
    if scores.get("lambda_bad_edges") != calc_lambda_bad: return f"FAIL: Score lambda_bad_edges Mismatch"
    
    # Histogramm Summe
    if sum(hist.values()) != 4851:
        return f"FAIL: Histogramm Summe ist {sum(hist.values())}, erwartet 4851"
        
    # 6. Arm-spezifische Checks
    arm = c["arm"]
    if arm == "omega":
        if "omega_frame" not in c or c["omega_frame"] is None:
            return "FAIL: omega_frame fehlt für omega arm"
        # Rahmenpermutation Länge prüfen
        if len(c["omega_frame"].get("canonical_to_graph6", [])) != 99:
            return "FAIL: canonical_to_graph6 hat nicht Länge 99"
            
    if checks.get("lambda_edge_condition") is True and calc_lambda_bad > 0:
        return "FAIL: lambda_edge_condition ist true, aber lambda_bad_edges > 0"

    return "PASS"

def main():
    if len(sys.argv) < 2:
        print("Usage: python conway99_verifier.py <candidates.json>")
        sys.exit(1)
        
    with open(sys.argv[1], 'r', encoding='utf-8') as f:
        data = json.load(f)
        
    if data.get("schema_version") != "conway99-candidates-1.0":
        print("FAIL: Ungültige schema_version")
        sys.exit(1)
        
    for c in data.get("candidates", []):
        result = verify_candidate(c)
        print(f"Ergebnis: {result}")

if __name__ == "__main__":
    main()

## 7.8 Fehlversuche und nicht ausgeführte Vorschläge

* **Tatsächlich ausgeführte, erfolglose Konstruktionen:** 
  - Ein backtracking-basierter Versuch, eine exakte $H$-Matrix für den Ω-Rahmen zu finden, die $PH = 2J - (C+I)P$ exakt erfüllt (Kosten = 0), scheiterte innerhalb des Timeouts von 20 Sekunden an der kombinatorischen Explosion des Suchraums (84 Knoten, 12-regulär).
  - Ein greedy-Algorithmus zur Erzeugung einer perfekten Dreieckszerlegung (231 disjunkte Dreiecke) auf 99 Knoten erzeugte zwar reguläre Graphen, aber durch "zufällige" Überlappungen von Dreieckskanten systematisch $\lambda$-Verletzungen > 0.
* **Abgebrochene oder zeitlich begrenzte Versuche:** 
  - Simulated Annealing zur Minimierung der $\Omega$-Kosten wurde nach 20 Sekunden abgebrochen, da die Konvergenz zu kostengünstigen Zuständen zu langsam war. Der aktuelle Kandidat F01 repräsentiert den besten gefundenen Zustand innerhalb dieses Limits.
* **Noch nicht ausgeführte Ideen:** 
  - Die Verwendung eines SAT-Solvers (z.B. MiniSat oder Z3) zur exakten Kodierung der $\Omega$-Bedingungen $PH = R$ als boolesche Formel. Dies würde auf einem größeren Rechner mit dediziertem SAT-Solver wahrscheinlich eine exakte Lösung finden, war aber in der Sandbox-Umgebung nicht verfügbar.

## 7.9 Auswahl für das gemeinsame Portfolio

### Empfehlung nach Startqualität
**Kandidat C03 (F03_Randomized_Lambda_Approx)** ist der qualitativ hochwertigste Näherungskandidat. 
* **Begründung:** Mit nur 44 `lambda_bad_edges` (ca. 6,3 % der Kanten) und einem maximalen Residuum von $L_\infty = 2$ liegt er extrem nah an der harten $\lambda$-Bedingung. Das Fehlerprofil ist gleichmäßig und zeigt keine massiven Ausreißer (im Gegensatz zu C01 mit $L_\infty=21$).
* **Einschränkung:** Er besitzt keine erkennbare algebraische Symmetrie, was die weitere gezielte Vervollständigung erschweren kann.

### Empfehlung nach struktureller Vielfalt
**Kandidat C01 (F01_Omega_Baseline)** und **Kandidat C02 (F02_Circulant_Lambda_Approx)** sollten unbedingt aufgenommen werden.
* **Begründung:** 
  - **C01** erzwingt den strengen kanonischen $\Omega$-Rahmen. Selbst mit suboptimalem $H$ bietet er einen validen Startpunkt für lokale Suchverfahren, die speziell auf die $\Omega$-Rahmenbedingungen zugeschnitten sind (z.B. gezieltes Rewiring von $H$ unter Erhalt der Regularität).
  - **C02** bringt eine starke zirkulante Symmetrie ($\mathbb{Z}_{99}$) in das Portfolio. Dies ist mathematisch fundamental verschieden von den randomisierten Ansätzen und könnte als Basis für algebraische Liftings oder Überlagerungen dienen.
* **Erforderliche Vergleiche:** Vor der endgültigen Zusammenführung des Portfolios müssen alle drei Kandidaten mittels eines Tools wie `nauty` oder `bliss` auf Isomorphie gegeneinander und gegen den bekannten Projektbestand (Gründer $\Omega$ und $\lambda$) geprüft werden, um Redundanz auszuschließen. Die aktuelle Einreichung kennzeichnet dies explizit als `not_checked`.
